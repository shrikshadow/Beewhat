Here's what Verity is built on:

Database: Supabase PostgreSQL

  • Every piece of app data lives there: users, login sessions, expert profiles, uploaded documents, bookings, payments, reviews and settings. MongoDB isn't used.
  • Changes to the tables are tracked as Alembic migrations in backend/alembic/.
  • The database itself rejects overlapping bookings for the same expert, using a PostgreSQL btree_gist exclusion constraint.
  • The app connects through Supabase's transaction pooler (port 6543).

Backend: Python (FastAPI)

  • SQLAlchemy 2 with the asyncpg driver handles database access, and Pydantic v2 validates requests and responses.
  • Login uses email + password; passwords are hashed with bcrypt. Sessions are stored in Postgres and sent to the browser as httpOnly cookies.
  • There are three roles: user, expert and admin. Each user's role is re-checked from the database on every request.

Frontend: React 19 + TypeScript

  • Built with Vite, styled with Tailwind CSS v4 and shadcn/ui components.
  • TanStack Query handles data loading and caching; React Router handles page navigation.
  • Fonts are Plus Jakarta Sans, DM Sans and JetBrains Mono; icons come from lucide-react.

Mocked by design: payments, the OTP step (always accepts 123456) and live sessions. No outside payment or email services are connected.

You have two ways to download all the files created by the agent on Emergent:

Option 1: Push to GitHub (Recommended)

This is the primary method to get your complete codebase:

  1. Click the Save button in the chat input bar
  2. Select "Save to GitHub"
  3. Connect your GitHub account (if not already connected) via OAuth
  4. Select or create a repository (type at least 3 characters to search)
  5. Select or create a branch
  6. Click "Save to GitHub" to push all your code

Once pushed to GitHub, clone it to your local machine:

git clone <your-repository-url>

Important notes:

  • GitHub push requires a paid plan (Standard or above)
  • Environment variables and database data are excluded for security (you'll need to set those up separately)
  • node_modules are excluded
  • Wait for the agent to finish working before pushing to avoid incomplete snapshots

Option 2: VS Code Editor View (Manual Copy)

Available on all plans including Free:

  1. Click the "Code" button in the top toolbar
  2. Copy the password shown in the modal
  3. Click "Open in browser" and paste the password
  4. Browse your complete file tree in VS Code
  5. Manually copy files you need

This method lets you view and copy individual files but doesn't provide a bulk download.

Note: There is no "Download Code" button or archive export feature on Emergent. The GitHub push method is the standard way to get your complete codebase onto your local machine.

Some notes for your project in particular:

  • Your data won't be lost. Everything is stored in your own Supabase database, not here, so the code you download keeps working with the same data.
  • You'll need to add the database connection yourself. The GitHub copy leaves out your Supabase connection string for security. To run the app locally, create a file named backend/.env and add one line: DATABASE_URL=<your Supabase Transaction pooler URI>.
  • Starting fresh: if you point it at a new, empty Supabase database, run these commands from the backend folder:
    • alembic upgrade head creates the tables.
    • python seed.py adds the demo accounts and demo experts.
